## 最终验证

本机 Windows x64，Rust 1.99 stable；使用正常进程查询权限，关闭增量编译。以下命令全部通过：

```powershell
$env:CARGO_INCREMENTAL = '0'
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features --locked --offline -- -D warnings
cargo test --workspace --all-targets --all-features --locked --offline
cargo test --release --workspace --all-targets --all-features --locked --offline
```

调试版、优化版各 **41 项单元测试 + 4 项 CLI 集成测试，45/45 通过，无忽略项**。

- 可控边界用例覆盖：Unicode 字符边界、目录边界、UTF-16 原始数据、缓冲区多次扩容与异常长度、句柄表数量溢出、进程首尾记录、单模块失败保留成功结果、缓存复用、提前停止、展示信息失败及结束结果汇总。
- 真实 Windows 用例覆盖：本进程枚举、现有可执行文件和 DLL 的映射路径、超过 520 个 UTF-16 单元的本地 DLL 路径、长路径中文及未配对代理项文件与父目录扫描。
- 身份回归用例只结束测试自己创建的隐藏子进程：持有原句柄后故意改变保存的 PID，仍通过原句柄结束原子进程。没有结束无关进程。

- 严格沙箱曾拒绝系统句柄快照访问；上述完整 Windows 测试在正常查询权限下通过。没有把沙箱限制当作产品缺陷。

## 安全修复边界

旧路径为“外来模块文件名 → Locksmith 按文件名重新打开 → 之后才匹配目标”，可能在匹配前以扫描器身份访问远程共享。新路径为“保留的目标进程句柄 + 模块地址 → 查询已经存在的内存映射名 → 匹配目标”。PSAPI 长路径回退也查询同一映射，不引入按外来文件名打开的后备逻辑。

源码调用链检查加真实本地映射和长路径 DLL 用例验证了该边界；按 Codex Security fix-finding 流程完成独立调查及只读候选补丁复核。没有实际触发远程共享身份验证，不声明所有操作系统内部网络活动都不存在。用户明确选择的目标仍按正常文件接口打开，包括远程目标。

## 已认可的范围边界

- 本轮使用普通 Windows Unicode 忽略大小写规则；逐级 NTFS 大小写敏感设置已在讨论中延期，没有实现。
- 硬链接文件身份、junction 别名的目录祖先关系、多目标输入和每个进程的完整占用文件清单属于后续功能，不是本轮必要项。
- 权限、受保护进程、架构及扫描时对象变化可能使结果不完整。诊断保留总失败数和最多八条示例；不完整结果返回 2，成功匹配保留。
- 缓冲区容量与重试有上限，但单次文件系统调用仍同步，失去响应的驱动或远程提供者可能拖慢扫描。没有照搬上游的强制结束工作线程逻辑；辅助进程隔离需单独设计。
- 没有运行网络认证实验、完整 PowerToys 构建或跨架构测试；Windows CI 配置已提交，远端 CI 未触发或验证。MSIX、Microsoft Store 发布和命令别名注册未在本轮执行。
